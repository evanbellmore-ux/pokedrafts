# PokeDrafts release architecture

This document is the contract for the release-hardening work. Every page, migration, and helper is expected to follow it. When code and this document disagree, fix one of them in the same change.

## 1. Goals and constraints

- Ship a first public release of PokeDrafts: fantasy-football-style Pokemon draft leagues (create league, invite coaches, live snake draft with a pick timer, teams, schedule, results, standings, free-agent swaps).
- Every mutation that spans more than one row, or that must be validated against other rows, runs inside a Postgres function (`security definer`) so it is atomic and enforced server-side. The browser never writes directly to `leagues`, `league_members`, `league_invites`, `draft_picks`, `drafted_teams`, `league_matches`, or `league_news`.
- Reads stay client-side through the anon key and row-level security (RLS). A server Supabase client is used only in `proxy.ts`, the auth callback route, and the league layout (membership check and metadata).
- `leagues.commissioner_id` is the single source of truth for "who is the commissioner". `league_members.role` is display-only and is kept in sync by the functions.
- The backend must be reproducible from `supabase/migrations` on a fresh project, and the same files must apply cleanly to the existing project (everything is `if not exists` / `create or replace` / `drop policy if exists`).
- Next.js 16 conventions apply (see `node_modules/next/dist/docs`): `proxy.ts` not `middleware.ts`, `params` is a Promise, `metadata` only from server components, `error.tsx` uses `unstable_retry`, `next lint` is gone (plain `eslint`).

## 2. Glossary and copy rules

| Term | Meaning | Use in UI |
| --- | --- | --- |
| League | One draft league, owned by a commissioner | "League" |
| Commissioner | The user in `leagues.commissioner_id` | "Commissioner" |
| Coach | Any member of a league, including the commissioner when they also draft | "Coach"/"Coaches" (never "member" or "trainer" in user-facing copy) |
| Team | A coach's roster and team name | "Team", "My Team" |
| Pokémon | Always with the accent in user-facing copy | "Pokémon" |
| Draft pool / format | The point-priced list of Pokémon a league drafts from; a saved reusable list is a "draft format" | "Draft pool", "Draft format" |
| Free agent | An undrafted Pokémon after the draft | "Free agent" (never "free-agent" in labels: "Free agent swap limit", "Free agent swaps") |
| Matchup format | How the season schedule is built (`schedule_format`) | "Matchup format" on Settings and the Matches page, never "schedule format" |
| Create League | The primary call to action for a new league | "Create League" everywhere (dashboard buttons, the new-league page title and its submit button) |

- Status enums are never rendered raw. `league_matches.status`: `upcoming` -> "Upcoming", `completed` -> "Final". Roles: `commissioner` -> "Commissioner", `coach` -> "Coach".
- Errors shown to users come from `friendlyError()` (section 8.3). Raw PostgREST messages are logged, not displayed, except messages raised by our own functions, which are written for users.
- Success and error banners are visually distinct and have `role="status"` / `role="alert"`.

- Route groups do not change URLs. Existing URLs (`/dashboard`, `/builder`, `/leagues/new`, `/leagues/[id]/...`, `/login`, `/signup`, `/invite/[code]`) are preserved.
- Every `page.tsx` is a server component that exports `metadata` (or relies on the layout's `generateMetadata`) and renders one client component from a sibling file, e.g. `app/(app)/dashboard/page.tsx` renders `./DashboardClient.tsx`.
- A page's own components, hooks and pure helpers live next to it inside its route folder (the sibling files listed above); `app/lib` and `app/components` hold only the shared modules of section 8.1. `app/components/DraftBuilder.tsx` and the compatibility module `app/lib/pokemon/sprites.ts` no longer exist.
- The root layout reads the `pokedrafts-theme` cookie with `cookies()` to stamp `<html data-pokemon-theme>`, so every route is rendered dynamically on request (`next build` lists them all as `ƒ (Dynamic)`; nothing is prerendered). That is deliberate: the theme never flashes, and the proxy already makes every protected route per-user.
- There is no `app/(app)/error.tsx`; errors inside the app shell fall through to the root `app/error.tsx`.
- `LeagueNav` order: Overview, Draft, My Team, Matches, Standings, Free Agents, Pool, Settings. Settings shows for everyone but renders read-only for coaches. On small screens it is a horizontally scrollable strip. Active link has `aria-current="page"`.

### 3.1 proxy.ts

- Uses `@supabase/ssr` `createServerClient` with the `getAll` / `setAll` cookie adapter; refreshed cookies and the `Cache-Control` headers from `setAll` are copied onto every response, including redirects.
- Matcher: `['/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp|ico|txt|xml)$).*)']`.
- Public paths: `/`, `/login`, `/signup`, `/forgot-password`, `/update-password`, `/auth/callback`, `/invite/:code`.
- Unauthenticated request to a protected path -> redirect to `/login?next=<pathname+search>`.
- Authenticated request to `/`, `/login`, `/signup` -> redirect to `/dashboard` (or to `next` if present and relative), but only after `getUser()` confirmed the session with the auth server. A locally verified JWT (asymmetric signing keys) is not proof that GoTrue still accepts the session: the browser client's own `getUser()` may just have failed (auth server unreachable, user deleted or banned) and sent the user to `/login`, and bouncing them back on the strength of the cookie alone would loop until the access token expired. When the auth server cannot vouch for the session the public page renders; the cookies are kept (or cleared when it answers `session_not_found`). Protected paths stay optimistic (`getClaims()` only, no round trip). `tests/unit/proxy.test.ts` and the ES256 cases in `tests/unit/auth-session-real-clients.test.ts` cover this.
- `next` is only honoured when it starts with a single `/` (no `//`, no scheme).

### 3.2 Auth flows

- Sign up: `signUp({ email, password, options: { emailRedirectTo: `${origin}/auth/callback?next=<next or /dashboard>` } })`. Because email confirmation is enabled in the project, the page then shows "Check your email" (success style). If a session is returned immediately (confirmation disabled), navigate to `next`.
- Callback route: server client; if `code` -> `exchangeCodeForSession(code)`; if `token_hash` + `type` -> `verifyOtp`; on success redirect to validated `next` (default `/dashboard`). On failure redirect to `/login?error=auth` (invalid or expired link) or `/login?error=auth-device` (the PKCE verifier cookie is missing because the link was opened in another browser or device; the email is already confirmed), always keeping the validated `next` so an invited coach still lands on the invite after logging in. `next` may also be a same-origin URL of the form `/auth/callback?next=<path>` (what `{{ .RedirectTo }}` expands to in an email template); it is unwrapped one level and sanitized (`resolveCallbackNext`). The login page renders distinct copy for the two reasons (`app/lib/auth/callback.ts`).
- Login: `signInWithPassword`, then `router.replace(next)`; login page links to Sign up and Forgot password. Login and signup pages are real `<form>`s with labels, `type="email"`, `autoComplete`, pending state, and distinct error/success alerts.
- Forgot password: `resetPasswordForEmail(email, { redirectTo: `${origin}/auth/callback?next=<encoded withNextParam("/update-password", next)>` })`, i.e. `/update-password?next=<path>` when the user was heading somewhere (plain `/update-password` otherwise). Update password: `updateUser({ password })` then `router.replace(next)` (default `/dashboard`); section 8.3 has the whole round trip.
- Sign out: `signOutLocally(supabase.auth)` (`app/lib/auth/sign-out.ts`) calls `signOut({ scope: 'local' })` and returns `{ ok: true }` or `{ ok: false, message }` (message via `friendlyError`). auth-js still POSTs to `/logout` for a local scope and keeps the local session when that request fails with anything other than 401/403/404, so `AppNav` navigates (`router.replace('/login')` then `router.refresh()`) only on `ok`; otherwise it renders an error `Alert` ("You are still signed in on this device.") with Retry and stays on the page. `tests/unit/auth-sign-out.test.ts` covers both outcomes against the real auth-js client.
- Invite while logged out: page shows the league preview and a "Log in to join" / "Create an account" pair linking to `/login?next=/invite/CODE` and `/signup?next=/invite/CODE`.

## 4. Data model changes

Migration `00000000000000_base_schema.sql` creates every table with `create table if not exists`, matching the live project (introspected 2026-09-09):

- `leagues`(id uuid pk default gen_random_uuid(), name text not null, commissioner_id uuid not null, max_coaches int not null default 8, created_at timestamptz default now(), draft_format_id uuid references draft_formats(id) on delete set null, point_budget int default 100, draft_started bool default false, current_pick_number int default 1, picks_per_team int default 10, draft_completed bool default false, pick_timer_seconds int not null default 120, pick_started_at timestamptz default now(), auto_pick_in_progress bool not null default false, custom_pool jsonb, schedule_format text not null default 'round_robin', free_agent_swap_limit int not null default 3)
- `league_members`(id, league_id fk cascade, user_id uuid not null, role text not null default 'coach', joined_at, team_name text, draft_position int, free_agent_swaps_used int not null default 0)
- `league_invites`(id, league_id fk cascade, invite_code text not null, max_uses int not null default 1, used_count int not null default 0, expires_at timestamptz, created_at)
- `draft_formats`(id, name text not null, json jsonb not null, created_by uuid, created_at)
- `draft_picks`(id, league_id fk cascade, member_id fk cascade, pokemon_name text not null, points int not null, tier int not null, pick_number int not null, created_at)
- `drafted_teams`(id, league_id fk cascade, member_id fk cascade, pokemon jsonb not null, total_points int not null default 0, created_at)
- `draft_chat_messages` (message check length 1..500, index (league_id, created_at); the hardening migration adds the `before insert` trigger `draft_chat_messages_defaults` -> `_chat_message_defaults`, which assigns `id = gen_random_uuid()` and `created_at = now()` so a client-sent id or timestamp is ignored, never stored), `league_matches`, `league_news` (news_type check in ('free_agent','match_result'), message check length 1..500) as in the existing migrations; `leagues.schedule_format` check in ('round_robin','double_round_robin') from `20260626170000`
- `pokemon_dex`(id bigint generated pk, dex_number int not null, name text not null, created_at, sprite_url text, type1 text, type2 text), `pokemon_forms`(id bigint pk, name text not null, base_dex_number int, sprite_url text, pokeapi_slug text), `draft_order` (legacy, unused)

Migration `20260909120000_release_hardening.sql` (applied after the existing eight, and always the last file to run: the older files recreate the pre-release write policies and only this file removes them again) adds, all idempotently:

- Columns `leagues.draft_paused_at timestamptz` (null when running) and `leagues.draft_paused_total_seconds int not null default 0`.
- Data fixes, each reported with a `notice`/`warning`: `league_members.role` typo `commisioner` corrected and every row synced to `leagues.commissioner_id` (`commissioner` for that user, `coach` for everyone else); `league_members.team_name` trimmed and capped at 40 chars (blank -> null); `leagues.name` trimmed and capped at 60 (blank -> `Untitled League`); `draft_formats.name` trimmed and capped at 60 (blank -> `Untitled format`); format-based leagues without a pool array in `custom_pool` (the pre-release client read the format live) get a copy of their format's list through `_validate_pool` with `source: "format"` and `draft_format_id`, while a league whose format breaks the pool rules is skipped with a warning naming the league, the format and the entry and is listed by `_migration_report`; `leagues` numeric settings clamped into the documented ranges so the checks validate; duplicate `(league_id, user_id)` memberships from the old join flow removed when the duplicate owns no picks, team, matches, news or chat.
- Constraints, added only if missing and never failing on bad rows (a unique constraint that duplicates would violate is skipped, a check that rows violate is added `not valid`, both with a warning and a `_migration_report` row): `league_members` unique (league_id, user_id); check role in ('commissioner','coach'); check team_name null or length 1..40; unique (league_id, draft_position) deferrable initially deferred; check free_agent_swaps_used >= 0. `draft_picks` unique (league_id, pokemon_name), unique (league_id, pick_number). `drafted_teams` unique (league_id, member_id). `league_invites` unique (invite_code). `league_matches` check status in ('upcoming','completed'), unique (league_id, round_number, match_number). `leagues` check max_coaches between 2 and 24, point_budget between 1 and 10000, picks_per_team between 1 and 30, pick_timer_seconds between 10 and 3600, free_agent_swap_limit >= 0, name length 1..60. `draft_formats` check name length 1..60 and `json` is an object whose `pokemon` is an array of at most 2000 entries (entry-level rules are applied by `_validate_pool` when a league copies the format). `pokemon_dex` unique (dex_number).
- Indexes if missing: league_members(league_id), league_members(user_id), draft_picks(league_id, pick_number), league_matches(league_id), league_news(league_id, created_at desc), leagues(draft_format_id) (used by the `draft_formats` select policy).
- Realtime: add `draft_picks`, `leagues`, `league_members`, `league_matches`, `league_news`, `drafted_teams` to publication `supabase_realtime` when the publication exists (and is not "all tables") and the table is not already in it; `draft_chat_messages` was published by its own migration. A missing privilege is a warning that names the dashboard action.
- Storage: create public bucket `sprites` and the `Public read access to sprites` policy on `storage.objects` when the `storage` schema exists and the role may (warning otherwise).
- RLS: drop every existing policy on the app tables (loop over `pg_policies` for the listed tables), enable RLS, then create the complete policy set in section 6.
- Functions: drop the legacy `start_draft_timer`, `advance_draft_timer`, `complete_draft_timer`; create or replace everything in section 5, including the internal helpers and `_migration_report()`; revoke all API functions from `public`, `anon` and `authenticated` first and re-grant exactly the catalog.
- Report: the file ends with `select * from public._migration_report();`, so the SQL editor shows one row per open item (`severity`, `item`, `detail`, `action`: a `not valid` check, a skipped unique, a table missing from the publication, the bucket or its policy, a league without a usable pool) and no rows when nothing is left to fix. The function can be re-run at any time as the database owner (it is revoked from `anon` and `authenticated`); docs/schema.md, "Verifying the migration", lists every row kind.

Pool semantics: `leagues.custom_pool` (`{ version: "1.0", leagueName, pokemon: [{ name, points, tier }], source?: "format", draft_format_id? }`) is the only pool a league drafts from. `create_league` and `update_league_settings` copy the chosen format's list onto it at configuration time (`source: "format"`, `draft_format_id`) after `_validate_pool`; `update_league_pool` replaces it (no `source`); `reset_league_pool` copies the format again as it is right now; `reset_draft` keeps it; it is null only when no format was ever chosen or the format was removed from the settings. `draft_formats` is never read for a league's pool, so editing or deleting a format never changes what a league drafts from. The client reads `league.custom_pool?.pokemon ?? []` everywhere and reads `draft_formats` only for format names and to show the format behind a league.

## 5. RPC catalog

Conventions for every function:

- `language plpgsql security definer set search_path = public, extensions`; `revoke all on function ... from public, anon, authenticated; grant execute on function ... to authenticated;` (`get_server_time`, `get_invite_preview` and `is_league_member` are also granted to `anon`). Helpers prefixed with `_` have no API grants.
- The caller is `auth.uid()`; a null uid raises `not_authenticated`.
- Validation failures use `raise exception using message = '<user-facing sentence>', detail = '<snake_case_code>', errcode = 'P0001'` (`_fail`). The message is safe to display verbatim; `friendlyError()` shows it as is. Codes shared by many functions: `not_authenticated` (no user), `league_not_found`, `not_commissioner`, `not_a_member`.
- Row locks: every function that mutates a league first does `select ... from leagues where id = p_league_id for update` (`_lock_league`) so concurrent callers serialize.
- Internal helpers (not exported to the API): `_fail`, `_caller_uid`, `_lock_league`, `_league_commissioner_check(p_league_id)` (raises `not_commissioner`), `_member_for(p_league_id, uid)` (the caller's member row or `not_a_member`), `_validate_team_name`, `_visible_format`, `_validate_pool` (the pool contract: 1..2000 entries, unique non-empty trimmed names of at most 80 chars, integer points 1..20, `tier = 21 - points`; raises `invalid_pool` / `duplicate_pokemon` / `invalid_points` / `invalid_tier` naming the first offending entry; used by `update_league_pool`, `_format_pool` and the migration's format backfill), `_pool_rows` (a raw pokemon array as rows; lenient only for a list put on the row by hand: malformed entries skipped, duplicate names collapse to the most expensive entry), `_pool_json` (a league's pool as JSON: always `custom_pool`, never `draft_formats`), `_league_pool(p_league_id)` (the two combined: the effective pool as a set of (name text, points int, tier int)), `_format_pool` (a format as the `custom_pool` value that `create_league`, `update_league_settings` and `reset_league_pool` store, after `_validate_pool`; a failing format is refused with the same code and a message naming the format), `_positioned_members`, `_snake_member(p_league_id, p_pick_number)` (the on-clock member id), `_budget_fits` (the pure budget rule), `_pick_legal` (that rule for one candidate), `_best_available` (parses the pool once and applies the rule as a SQL filter, so auto-picks on a 2000-entry pool take milliseconds while the league row is locked), `_roster_total`, `_schedule_rows` (circle-method round robin, identical to `app/lib/league/schedule.ts`), `_new_invite_code`, `_create_invite`, `_setting_int`, `_advance_or_finalize`, `_finalize_draft`, `_pick_internal`, and `_migration_report` (section 4).

Schedule generation in SQL: build an ordered array of member ids (append a null "bye" when odd); for round r in 1..n-1 pair index i with n-1-i, skipping byes, alternating home/away per round; for double round robin append mirrored rounds with home and away swapped. ## 6. RLS policy set (complete)

All tables have RLS enabled. Only these policies exist after the hardening migration:

- `leagues`: select where `is_league_member(id)`; delete where `commissioner_id = auth.uid()`. No insert/update policies (functions only).
- `league_members`: select where `is_league_member(league_id)` (a `security definer` helper, so the policy does not evaluate itself recursively). No writes.
- `league_invites`: select where the caller is the league's commissioner. (Joiners go through `get_invite_preview`/`join_league`.)
- `draft_formats` (`authenticated` only): select where `created_by = auth.uid()`, or `created_by is null` (shared with everyone), or the row is the `draft_format_id` of a league the caller belongs to (`leagues.draft_format_id` + `is_league_member`, served by the `leagues(draft_format_id)` index), so the app can show the format behind a league through the `leagues -> draft_formats` embed; insert with check `created_by = auth.uid()`; update/delete where `created_by = auth.uid()` (no league is affected: each league holds its own copy in `custom_pool`). Column default `created_by uuid default auth.uid()`.
- `draft_picks`, `drafted_teams`, `league_matches`, `league_news`: select where `is_league_member(league_id)`. No writes.
- `draft_chat_messages`: select for league members; insert with check `user_id = auth.uid()` and a matching member row (existing policy, recreated). `id` and `created_at` are server-assigned by the `draft_chat_messages_defaults` trigger whatever the insert carries, so the room's `insert(...).select(...)` reads the stored values back.
- `pokemon_dex`, `pokemon_forms`: select for `authenticated`.
- `draft_order`: no policies (inaccessible).

The browser's only direct writes are `draft_formats` (own rows, from the Pool Builder), `draft_chat_messages` inserts (draft room) and `leagues` deletes (dashboard). PostgREST reports an update or delete that a policy filtered out as a success with zero rows, so those calls end with `.select("id").single()` (insert/update, turning the no-op into `PGRST116`) or `.select("id")` with an empty array treated as "no permission" (delete). Every other direct write to `leagues`, `league_members`, `league_invites`, `draft_picks`, `drafted_teams`, `league_matches` or `league_news`, and every call to a dropped or unknown RPC, is reported by `node scripts/check-client-contract.mjs` (exit 1), which `tests/db/client-contract.test.ts` also runs against the working tree.

## 7. Realtime

- Draft room (`useDraftRoom.ts`) subscribes on one channel (`league:<leagueId>:draft:<n>`, numbered by a module-level counter of its own) to `draft_picks`, `leagues`, `league_members` (filtered by league) and `draft_chat_messages` inserts, with a status callback: on `SUBSCRIBED` refetch; on `CHANNEL_ERROR`/`TIMED_OUT`/`CLOSED` show a "Reconnecting..." banner and fall back to polling every 10 s while the draft is active. Refetch on `visibilitychange` to visible. A dropped channel is announced once: the `DraftStatusBanner` (`role="status"`) carries it, while the Live pill in the page header and the explanatory notice under it are plain, non-live markup.
- Every client (not only the on-clock coach) calls `auto_pick_if_expired` once when its local timer reaches 0 and then every 5 s while it stays at 0.
- `loadDraft` carries a request generation counter; responses from stale generations are ignored. The overview, standings and pool pages pair the section 8.2 `active` flag with the same kind of counter, so a reload triggered by a realtime event or a Retry is never overwritten by a slower, older response.
- The other league pages share `useLeagueRealtime` (`app/(app)/leagues/[leagueId]/useLeagueRealtime.ts`): one channel per page, every listed table filtered by the league id (`id=eq.` for `leagues`, `league_id=eq.` elsewhere), a status callback that drives the Live / Connecting / Reconnecting pill (`LiveStatusPill`, a `role="status"` region) and refetches when the channel comes back, and `removeChannel` on unmount. Tables watched: overview `leagues`, `league_members`, `league_matches`, `league_news` (a `leagues` change calls the provider's `refresh()` so the phase card, coach list and invite seat count follow draft start, transfers and joins); standings `league_matches`, `league_members` (team renames); pool `leagues`; free agents `leagues`, `drafted_teams`, `league_news` (the `leagues` row too, so a changed swap limit or a draft reset shows without a manual refresh; the reset's `drafted_teams` deletes would not pass the league filter on their own); matches `league_matches`. The team page has no subscription.
- Every subscription uses a unique channel topic (`league:<id>:<page>:<n>`): supabase-js `channel(topic)` returns the existing channel for a repeated topic, and React's double-invoked development effects would otherwise re-attach to a channel that the first cleanup is still tearing down and never report "Live".

### 8.2 Data loading pattern

```ts
const supabase = useMemo(() => createClient(), []);
const load = useCallback(async () => { ... }, [supabase, leagueId]);
useEffect(() => {
  let active = true;
  void load().then(() => { if (!active) return; ... });
  return () => { active = false; };
}, [load]);
```

- Every page has `loading` state and renders skeletons; empty-state copy is gated on `!loading`.
- Every query destructures `error`; on error render an `Alert variant="error"` with a Retry button.
- Client code never treats `getUser()`'s `data.user === null` as "logged out": auth-js keeps the local session for a network failure, a 5xx or a rejected token, so `router.push("/login")` would only bounce back through the proxy. Use `getCurrentUser(supabase.auth)` (`app/lib/auth/current-user.ts`): `signed-in` carries `{ id, email }`; `signed-out` means auth-js has no local session (or has just cleared it for `session_not_found`), so `router.replace("/login")` is safe and the proxy agrees; `error` is rendered with `Alert variant="error"` and a Retry action while the session is kept. `tests/unit/auth-current-user.test.ts` covers the branches against the real auth-js client and lists the call sites (update-password, invite, dashboard, new league, builder).
- The dashboard, new-league and builder pages classify the session with `getCurrentUser` and, for `signed-out`, render a warning `Alert` with a "Log in" link (the new-league form also disables its submit button) instead of redirecting: the proxy already gates these routes, so a signed-out result there means the session vanished mid-visit. Inside a league the user comes from `useLeague()`; a league page never calls `getUser()` and never redirects.
- Pages that reload on realtime events or Retry keep a request-generation counter (`useRef`) next to the `active` flag so a stale response never overwrites a newer one (section 7).
- Success messages are set after the reload completes; loaders never clear messages.
- No `eslint-disable` comments for hooks rules; fix the dependency instead. The only `eslint-disable` in `app/` is the `@next/next/no-img-element` line in `PokemonSprite`. No `window.alert` and no `console.log`; `console.error` is used only by the error boundary and `friendlyError` (section 2: raw errors are logged, not displayed).

### 8.3 Forms and actions

- Inputs live in `<form onSubmit>`; buttons that mutate show a pending state and are disabled while pending.
- Numeric inputs parse with `Number.parseInt`, reject NaN, and clamp to the ranges in section 4 before calling the RPC; the RPC re-validates.
- Destructive actions (delete league, reset draft, regenerate schedule with results, undo move, remove member) use `Dialog` with a typed confirmation where the current app already does (league name) or an explicit confirm button otherwise.
- The overview news feed offers Undo only on each team's newest `free_agent` row among the loaded rows (`undoableNewsIds` in `NewsFeed.tsx`); `undo_free_agent_move` still validates every call and its message is shown inside the dialog. Regenerating an invite uses the same `Dialog danger` on the overview and on Settings (title "Regenerate invite link?", confirm "Regenerate link", description saying the old link stops working); the Settings card hides the link and its buttons once the draft has started, since `join_league` refuses new coaches from then on.
- A league delete that returns zero rows (the league is already gone, or the caller is no longer its commissioner) closes the dialog, reloads the list and shows a warning banner instead of an error inside the dialog.
- The draft-order Move up / Move down buttons stay rendered, disabled, at the ends of the list; after a move, focus goes back to the pressed button or, when that button is disabled now, to its sibling (React relocates the moved row's DOM node, which would otherwise drop focus to the body).
- Password recovery keeps `next` (the page the user was heading for, e.g. an invite) across the whole round trip: both "Forgot your password?" links on the login form are `withNextParam("/forgot-password", next)`; `forgot-password/page.tsx` reads `next` from `searchParams` through `sanitizeNextPath` and the form sends `redirectTo = <origin>/auth/callback?next=<encoded withNextParam("/update-password", next)>`, i.e. `/update-password?next=<path>` (plain `/update-password` for the default destination); the callback route unwraps and re-validates it with `resolveCallbackNext`; `update-password/page.tsx` sanitizes `next` again (and refuses `/update-password` itself) and the form runs `router.replace(next)` after `updateUser({ password })` instead of always going to `/dashboard`. The logged-out state's "Request a new link" and the standing "Back to log in" link carry `next` too. `tests/unit/shared-ui-review.test.ts` replays the encoded value through `resolveCallbackNext` for both the PKCE `?code` and the token-hash `next={{ .RedirectTo }}` link shapes.
- The browser's only direct writes are the ones section 6 allows: `draft_formats` in the Pool Builder (insert with `.select("id").single()`, update/delete with `.eq("id", ...).select("id")`, `created_by` never sent), `draft_chat_messages` inserts in the draft room, and the league delete on the dashboard (`.delete().eq("id", id).select("id")`, an empty result treated as "nothing deleted / no permission"). Everything else goes through `rpc.*`; after any mutation that changes the league or member row the page calls `refresh()` from `useLeague()`. The Pool page re-reads `leagues.custom_pool` before saving and refuses to overwrite a pool that changed since editing began (the RPC itself is last-writer-wins).

### 8.4 Accessibility

- Every control has a label (`Field`) or `aria-label`; tables use `scope="col"`; navs have `aria-label`; active nav link has `aria-current`; toggle buttons expose `aria-pressed`; the draft timer region is `aria-live="off"` with a separate `role="status"` banner announcing "You are on the clock"; dialogs trap focus and restore it. `LiveStatusPill` (`app/(app)/leagues/[leagueId]/LiveStatusPill.tsx`, the `role="status"` pill shared by the overview news feed, standings, pool, free-agent and matches pages) puts a visually hidden `Live updates: ` prefix before its label inside the region, so a state change is announced as "Live updates: Reconnecting" rather than a bare "Reconnecting" (a live region reads its changed content, so the subject has to be content, not an `aria-label`); it is the same prefix the draft room's `LivePill` uses, and the visible pill text stays the bare word. `tests/unit/shared-ui-review.test.ts` asserts both.
- Buttons whose visible text repeats on every row (Delete on the dashboard; Make commissioner, Remove and Leave league on the coaches lists; Add on the free-agent list; Remove on the pool) carry an `aria-label` that contains the visible text and names the row, e.g. `Delete <league name>`, `Make commissioner: <team>`, so the visible label stays part of the accessible name (WCAG 2.5.3). `tests/unit/league-pages-review.test.ts` checks this for the league pages.
- Landmarks: the signed-in shell is `AppNav` + `<main id="main-content">`; the landing page (`app/page.tsx`) renders its `<header>` and `<footer>` as siblings of `<main id="main-content">`, not inside it, so they are exposed as the banner and contentinfo landmarks.
- Inline text links (the auth pages' "Forgot your password?", "Sign up", "Log in", "Back to log in", "request a new one", the auth layout's brand link and the landing footer links) use `linkClassName` from `app/lib/theme` (`rounded focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-focus focus-visible:ring-offset-2 focus-visible:ring-offset-bg`, the Button ring) plus their own colour classes, never a bare `hover:underline` with the browser outline. `tests/unit/shared-ui-review.test.ts` checks every `<Link>` in those files.
- Theme picker uses a native `<select>` styled to match; below `sm` it is a 40px icon-only control (palette icon + accent swatch, transparent value text, hidden chevron) so the AppNav fits a 320px viewport.
- Focus indicators use the opaque per-theme `--color-focus` token (`focus-visible:ring-2 focus-visible:ring-focus`; inputs use `focus:border-focus focus:ring-1 focus:ring-focus`), never the translucent `accent-border`, so the ring is at least 3:1 against `bg`, `panel` and `panel-hover` in every palette (WCAG 1.4.11). `tests/unit/theme-contrast.test.ts` asserts this.
- Unfocused text fields and selects (`Input`, `Select`, `NumberInput`, the ThemeToggle `<select>`) draw their boundary with the opaque per-theme `--color-control-border` token, which is at least 3:1 against `bg` (the field fill), `panel` and `panel-hover` in every palette (WCAG 1.4.11); the translucent `border-line` is only for decorative card and divider lines. `tests/unit/ui-a11y-review.test.ts` asserts this.
- `TypeBadge` applies the canonical type colours (`pokemonTypeColours` in `app/lib/theme`) as inline styles rather than palette utilities, so no theme recolours them; a Grass badge is green in every theme. These two files are the only inline colour styles in the app. The root layout exports `generateViewport` (not a static `viewport`): it reads the theme cookie like the layout body does and sets `themeColor` to `themeBackgrounds[theme]` (the palette's `--type-bg`) so the mobile browser chrome matches the page background; that is a `<meta>` value, not a class. It is re-resolved per request, and `ThemeProvider.setTheme` also writes the same `themeBackgrounds` value into the rendered `<meta name="theme-color">`, so a theme change made with the picker reaches the chrome immediately as well as on the next navigation or refresh.

### 8.5 Mobile

- Wide tables sit in `TableWrap`; below `md` the draft pool, free agents, pool, builder, team and standings pages render card rows instead of tables (any table with more than three columns). The draft room's pool, the pool, free-agent, team and standings pages and the builder mount only one of table/cards at a time through a `matchMedia` hook (`useMinWidthMd` / `useMediaQuery`, `useSyncExternalStore` with a mobile server snapshot) so a 2000-row pool is never rendered twice and per-row ids (the `aria-describedby` reasons on the free-agent Add buttons) stay unique. Nothing may overflow a 375px viewport: user-entered names are wrapped with `wrap-anywhere` (plus `min-w-0` on flex items) wherever they can appear without spaces (`RoundCard`, `PageHeader`, `Dialog`, `Alert`); on the league pages the truncating team names inside `flex-wrap` rows (`CoachesList`, `CoachesCard`, `TeamCard`, `DraftOrderCard`, the free-agents header) carry `min-w-0`, and the dashboard league card wraps the league and team names the same way (`PageHeader` covers the overview and My Team headers).
- Long lists are bounded: the overview news feed loads 20 rows per "Load more" on a `created_at` cursor; the pool page shows 100 rows at a time with "Show more" (search applies to the whole list); the draft-room pool renders at most 300 matching rows and asks for a narrower search beyond that (the legal list, affordability, auto-pick and Force pick are still computed over the whole undrafted pool); the free-agent list pages 60 rows; the builder pages 100 rows; the draft chat loads the newest 100 messages.
- AppNav collapses to brand + icon buttons below `sm`; LeagueNav is a horizontal scroll strip; the draft room mobile panel bar is sticky under the header (`top-16`, the AppNav height) with `aria-pressed` panel buttons and an unread badge on Chat that counts messages received while the chat panel was hidden.

### 8.6 Theme tokens

`globals.css` defines the 18 `--type-*` palettes (keep values, fix `--type-on-accent` to a light colour for fire, water, grass, fighting, poison, flying, psychic, rock, ghost, dragon, dark, fairy) and maps them to Tailwind 4 tokens in `@theme inline`:

```
--color-bg, --color-panel, --color-panel-hover, --color-line, --color-line-strong, --color-control-border,
--color-accent, --color-accent-hover, --color-accent-soft, --color-accent-border, --color-accent-text,
--color-text, --color-muted, --color-faint, --color-on-accent, --color-focus,
--color-danger, --color-danger-soft, --color-danger-strong, --color-danger-strong-hover, --color-on-danger,
--color-warning, --color-warning-soft, --color-success, --color-success-soft
```

`--type-focus` is an opaque light tint per palette (currently equal to `--type-accent-text`). `--type-control-border` is an opaque mid tint per palette (`--type-accent-text` composited at 50% over `--type-bg`) used only for form-control boundaries. `--type-danger` (#f87171) is a text/icon colour for dark panels; the danger Button fill is `--type-danger-strong` (#b91c1c, 6.5:1 with `--type-on-danger` white) hovering to `--type-danger-strong-hover` (#991b1b). `--type-faint` (#96908b, shared by every palette) is used for placeholders and 12px labels and must stay >= 4.5:1 on `--type-bg` and `--type-panel` of all 18 themes; `--type-accent-hover` is only ever a primary Button fill and must keep >= 4.5:1 under `--type-on-accent`, so the five palettes with light on-accent text (fighting, poison, ghost, dragon, dark) hover darker than their accent. `tests/unit/theme-contrast-review.test.ts` asserts both. `--type-muted` is #a8a29e; electric, ice, ground and bug lighten it slightly (per-palette override) so a titled `Alert` body (`text-muted` over the translucent soft fills on `panel`) stays >= 4.5:1 in every palette; `tests/unit/ui-a11y-lens.test.ts` asserts this for all four variants.

Pages use `bg-bg`, `bg-panel`, `border-line`, `bg-accent text-on-accent`, `text-muted`, etc., and nothing else: no page or component uses stone/amber/emerald/sky (or red/green/yellow/gray/zinc/neutral) Tailwind colour utilities or a hex colour in a className, so the `[data-pokemon-theme]` stone/amber/emerald `!important` "legacy overrides" block has been deleted from `globals.css` (the file contains no `!important` at all). `tests/unit/legacy-overrides.test.ts` fails if such a utility, a hex className or the block comes back. The theme is stored in the `pokedrafts-theme` cookie (1 year, SameSite=Lax) and rendered server-side on `<html data-pokemon-theme>` and, through `generateViewport` + `themeBackgrounds`, as the `theme-color` meta; the base `:root` palette equals the `normal` theme so there is never a flash. The body font is `var(--font-sans)` (Geist).

## 10. Deployment hand-off

1. Apply `supabase/migrations/*.sql` in order to the live project (Supabase SQL editor or `supabase db push`). The hardening migration resets all policies on the app tables and drops the three legacy timer functions. Until it is applied, every function it introduces returns `PGRST202`, which the client shows as "This feature is not available yet, please try again later." with a Retry button; the first place a visitor meets it is `/invite/<code>` logged out (`get_invite_preview`), so open that page after applying and confirm the league preview renders before shipping.
2. In Supabase Auth settings add `<site>/auth/callback` to the redirect allow-list and set the Site URL.
   Change the "Confirm signup" and "Reset password" email templates to token-hash links so they work when opened in a different browser or device than the one that started the flow (PKCE `{{ .ConfirmationURL }}` links need the verifier cookie and otherwise land on `/login?error=auth-device`):
   `{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=signup&next={{ .RedirectTo }}` for signup and `...&type=recovery&next={{ .RedirectTo }}` for recovery. `{{ .RedirectTo }}` is the `emailRedirectTo` / `redirectTo` value (`<origin>/auth/callback?next=<path>`), which the route unwraps to `<path>`.
3. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` on the host. The service-role key is only needed by `scripts/` (`.env.scripts`).
4. Seed `pokemon_dex` with `npm run seed:dex`, upload sprites to the `sprites` bucket, then `npm run seed:sprites` and `npm run seed:types`.
5. Run `node scripts/check-client-contract.mjs` on the branch being deployed (exit 0) and ship the client and the hardening migration in the same window (README, "The deployed client must be on the RPC catalog first").
