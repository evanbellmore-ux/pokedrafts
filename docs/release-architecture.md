# PokeDrafts release architecture

This document is the contract for the release-hardening work. Every page, migration, and helper is expected to follow it. When code and this document disagree, fix one of them in the same change.

## 1. Goals and constraints

- Ship a first public release of PokeDrafts: fantasy-football-style Pokemon draft leagues (create league, invite coaches, live snake draft with a pick timer, teams, schedule, results, standings, free-agent swaps).
- Every mutation that spans more than one row, or that must be validated against other rows, runs inside a Postgres function (`security definer`) so it is atomic and enforced server-side. The browser never writes directly to `leagues`, `league_members`, `league_invites`, `draft_picks`, `drafted_teams`, `league_matches`, or `league_news`.
- Reads stay client-side through the anon key and row-level security (RLS). A server Supabase client is used only in `proxy.ts`, the auth callback route, and the league layout (membership check and metadata).
- `leagues.commissioner_id` is the single source of truth for "who is the commissioner". `league_members.role` is display-only and is kept in sync by the functions.
- The backend must be reproducible from `supabase/migrations` on a fresh project, and the same files must apply cleanly to the existing project (everything is `if not exists` / `create or replace` / `drop policy if exists`).
- Next.js 16 conventions apply (see `node_modules/next/dist/docs`): `proxy.ts` not `middleware.ts`, `params` is a Promise, `metadata` only from server components, `error.tsx` uses `unstable_retry`, `next lint` is gone (plain `eslint`).

## 2. Glossary and copy rules

| Term | Meaning | Use in UI |
| --- | --- | --- |
| League | One draft league, owned by a commissioner | "League" |
| Commissioner | The user in `leagues.commissioner_id` | "Commissioner" |
| Coach | Any member of a league, including the commissioner when they also draft | "Coach"/"Coaches" (never "member" or "trainer" in user-facing copy) |
| Team | A coach's roster and team name | "Team", "My Team" |
| Pokémon | Always with the accent in user-facing copy | "Pokémon" |
| Draft pool / format | The point-priced list of Pokémon a league drafts from; a saved reusable list is a "draft format" | "Draft pool", "Draft format" |
| Free agent | An undrafted Pokémon after the draft | "Free agent" (never "free-agent" in labels: "Free agent swap limit", "Free agent swaps") |
| Matchup format | How the season schedule is built (`schedule_format`) | "Matchup format" on Settings and the Matches page, never "schedule format" |
| Create League | The primary call to action for a new league | "Create League" everywhere (dashboard buttons, the new-league page title and its submit button) |

- Status enums are never rendered raw. `league_matches.status`: `upcoming` -> "Upcoming", `completed` -> "Final". Roles: `commissioner` -> "Commissioner", `coach` -> "Coach".
- Errors shown to users come from `friendlyError()` (section 8.3). Raw PostgREST messages are logged, not displayed, except messages raised by our own functions, which are written for users.
- Success and error banners are visually distinct and have `role="status"` / `role="alert"`.

- Route groups do not change URLs. Existing URLs (`/dashboard`, `/builder`, `/leagues/new`, `/leagues/[id]/...`, `/login`, `/signup`, `/invite/[code]`) are preserved.
- Every `page.tsx` is a server component that exports `metadata` (or relies on the layout's `generateMetadata`) and renders one client component from a sibling file, e.g. `app/(app)/dashboard/page.tsx` renders `./DashboardClient.tsx`.
- A page's own components, hooks and pure helpers live next to it inside its route folder (the sibling files listed above); `app/lib` and `app/components` hold only the shared modules of section 8.1. `app/components/DraftBuilder.tsx` and the compatibility module `app/lib/pokemon/sprites.ts` no longer exist.
- The root layout reads the `pokedrafts-theme` cookie with `cookies()` to stamp `<html data-pokemon-theme>`, so every route is rendered dynamically on request (`next build` lists them all as `ƒ (Dynamic)`; nothing is prerendered). That is deliberate: the theme never flashes, and the proxy already makes every protected route per-user.
- There is no `app/(app)/error.tsx`; errors inside the app shell fall through to the root `app/error.tsx`.
- `LeagueNav` order: Overview, Draft, My Team, Matches, Standings, Free Agents, Pool, Settings. Settings shows for everyone but renders read-only for coaches. On small screens it is a horizontally scrollable strip. Active link has `aria-current="page"`.

### 3.1 proxy.ts

- Uses `@supabase/ssr` `createServerClient` with the `getAll` / `setAll` cookie adapter; refreshed cookies and the `Cache-Control` headers from `setAll` are copied onto every response, including redirects.
- Matcher: `['/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp|ico|txt|xml)$).*)']`.
- Public paths: `/`, `/login`, `/signup`, `/forgot-password`, `/update-password`, `/auth/callback`, `/invite/:code`.
- Unauthenticated request to a protected path -> redirect to `/login?next=<pathname+search>`.
- Authenticated request to `/`, `/login`, `/signup` -> redirect to `/dashboard` (or to `next` if present and relative), but only after `getUser()` confirmed the session with the auth server. A locally verified JWT (asymmetric signing keys) is not proof that GoTrue still accepts the session: the browser client's own `getUser()` may just have failed (auth server unreachable, user deleted or banned) and sent the user to `/login`, and bouncing them back on the strength of the cookie alone would loop until the access token expired. When the auth server cannot vouch for the session the public page renders; the cookies are kept (or cleared when it answers `session_not_found`). Protected paths stay optimistic (`getClaims()` only, no round trip). `tests/unit/proxy.test.ts` and the ES256 cases in `tests/unit/auth-session-real-clients.test.ts` cover this.
- `next` is only honoured when it starts with a single `/` (no `//`, no scheme).

### 3.2 Auth flows

- Sign up: `signUp({ email, password, options: { emailRedirectTo: `${origin}/auth/callback?next=<next or /dashboard>` } })`. Because email confirmation is enabled in the project, the page then shows "Check your email" (success style). If a session is returned immediately (confirmation disabled), navigate to `next`.
- Callback route: server client; if `code` -> `exchangeCodeForSession(code)`; if `token_hash` + `type` -> `verifyOtp`; on success redirect to validated `next` (default `/dashboard`). On failure redirect to `/login?error=auth` (invalid or expired link) or `/login?error=auth-device` (the PKCE verifier cookie is missing because the link was opened in another browser or device; the email is already confirmed), always keeping the validated `next` so an invited coach still lands on the invite after logging in. `next` may also be a same-origin URL of the form `/auth/callback?next=<path>` (what `{{ .RedirectTo }}` expands to in an email template); it is unwrapped one level and sanitized (`resolveCallbackNext`). The login page renders distinct copy for the two reasons (`app/lib/auth/callback.ts`).
- Login: `signInWithPassword`, then `router.replace(next)`; login page links to Sign up and Forgot password. Login and signup pages are real `<form>`s with labels, `type="email"`, `autoComplete`, pending state, and distinct error/success alerts.
- Forgot password: `resetPasswordForEmail(email, { redirectTo: `${origin}/auth/callback?next=<encoded withNextParam("/update-password", next)>` })`, i.e. `/update-password?next=<path>` when the user was heading somewhere (plain `/update-password` otherwise). Update password: `updateUser({ password })` then `router.replace(next)` (default `/dashboard`); section 8.3 has the whole round trip.
- Sign out: `signOutLocally(supabase.auth)` (`app/lib/auth/sign-out.ts`) calls `signOut({ scope: 'local' })` and returns `{ ok: true }` or `{ ok: false, message }` (message via `friendlyError`). auth-js still POSTs to `/logout` for a local scope and keeps the local session when that request fails with anything other than 401/403/404, so `AppNav` navigates (`router.replace('/login')` then `router.refresh()`) only on `ok`; otherwise it renders an error `Alert` ("You are still signed in on this device.") with Retry and stays on the page. `tests/unit/auth-sign-out.test.ts` covers both outcomes against the real auth-js client.
- Invite while logged out: page shows the league preview and a "Log in to join" / "Create an account" pair linking to `/login?next=/invite/CODE` and `/signup?next=/invite/CODE`.

## 4. Data model changes

Migration `00000000000000_base_schema.sql` creates every table with `create table if not exists`, matching the live project (introspected 2026-09-09):

- `leagues`(id uuid pk default gen_random_uuid(), name text not null, commissioner_id uuid not null, max_coaches int not null default 8, created_at timestamptz default now(), draft_format_id uuid references draft_formats(id) on delete set null, point_budget int default 100, draft_started bool default false, current_pick_number int default 1, picks_per_team int default 10, draft_completed bool default false, pick_timer_seconds int not null default 120, pick_started_at timestamptz default now(), auto_pick_in_progress bool not null default false, custom_pool jsonb, schedule_format text not null default 'round_robin', free_agent_swap_limit int not null default 3)
- `league_members`(id, league_id fk cascade, user_id uuid not null, role text not null default 'coach', joined_at, team_name text, draft_position int, free_agent_swaps_used int not null default 0)
- `league_invites`(id, league_id fk cascade, invite_code text not null, max_uses int not null default 1, used_count int not null default 0, expires_at timestamptz, created_at)
- `draft_formats`(id, name text not null, json jsonb not null, created_by uuid, created_at)
- `draft_picks`(id, league_id fk cascade, member_id fk cascade, pokemon_name text not null, points int not null, tier int not null, pick_number int not null, created_at)
- `drafted_teams`(id, league_id fk cascade, member_id fk cascade, pokemon jsonb not null, total_points int not null default 0, created_at)
- `draft_chat_messages` (message check length 1..500, index (league_id, created_at); the hardening migration adds the `before insert` trigger `draft_chat_messages_defaults` -> `_chat_message_defaults`, which assigns `id = gen_random_uuid()` and `created_at = now()` so a client-sent id or timestamp is ignored, never stored), `league_matches`, `league_news` (news_type check in ('free_agent','match_result'), message check length 1..500) as in the existing migrations; `leagues.schedule_format` check in ('round_robin','double_round_robin') from `20260626170000`
- `pokemon_dex`(id bigint generated pk, dex_number int not null, name text not null, created_at, sprite_url text, type1 text, type2 text), `pokemon_forms`(id bigint pk, name text not null, base_dex_number int, sprite_url text, pokeapi_slug text), `draft_order` (legacy, unused)

Migration `20260909120000_release_hardening.sql` (applied after the existing eight, and always the last file to run: the older files recreate the pre-release write policies and only this file removes them again) adds, all idempotently:

- Columns `leagues.draft_paused_at timestamptz` (null when running) and `leagues.draft_paused_total_seconds int not null default 0`.
- Data fixes, each reported with a `notice`/`warning`: `league_members.role` typo `commisioner` corrected and every row synced to `leagues.commissioner_id` (`commissioner` for that user, `coach` for everyone else); `league_members.team_name` trimmed and capped at 40 chars (blank -> null); `leagues.name` trimmed and capped at 60 (blank -> `Untitled League`); `draft_formats.name` trimmed and capped at 60 (blank -> `Untitled format`); format-based leagues without a pool array in `custom_pool` (the pre-release client read the format live) get a copy of their format's list through `_validate_pool` with `source: "format"` and `draft_format_id`, while a league whose format breaks the pool rules is skipped with a warning naming the league, the format and the entry and is listed by `_migration_report`; `leagues` numeric settings clamped into the documented ranges so the checks validate; duplicate `(league_id, user_id)` memberships from the old join flow removed when the duplicate owns no picks, team, matches, news or chat.
- Constraints, added only if missing and never failing on bad rows (a unique constraint that duplicates would violate is skipped, a check that rows violate is added `not valid`, both with a warning and a `_migration_report` row): `league_members` unique (league_id, user_id); check role in ('commissioner','coach'); check team_name null or length 1..40; unique (league_id, draft_position) deferrable initially deferred; check free_agent_swaps_used >= 0. `draft_picks` unique (league_id, pokemon_name), unique (league_id, pick_number). `drafted_teams` unique (league_id, member_id). `league_invites` unique (invite_code). `league_matches` check status in ('upcoming','completed'), unique (league_id, round_number, match_number). `leagues` check max_coaches between 2 and 24, point_budget between 1 and 10000, picks_per_team between 1 and 30, pick_timer_seconds between 10 and 3600, free_agent_swap_limit >= 0, name length 1..60. `draft_formats` check name length 1..60 and `json` is an object whose `pokemon` is an array of at most 2000 entries (entry-level rules are applied by `_validate_pool` when a league copies the format). `pokemon_dex` unique (dex_number).
- Indexes if missing: league_members(league_id), league_members(user_id), draft_picks(league_id, pick_number), league_matches(league_id), league_news(league_id, created_at desc), leagues(draft_format_id) (used by the `draft_formats` select policy).
- Realtime: add `draft_picks`, `leagues`, `league_members`, `league_matches`, `league_news`, `drafted_teams` to publication `supabase_realtime` when the publication exists (and is not "all tables") and the table is not already in it; `draft_chat_messages` was published by its own migration. A missing privilege is a warning that names the dashboard action.
- Storage: create public bucket `sprites` and the `Public read access to sprites` policy on `storage.objects` when the `storage` schema exists and the role may (warning otherwise).
- RLS: drop every existing policy on the app tables (loop over `pg_policies` for the listed tables), enable RLS, then create the complete policy set in section 6.
- Functions: drop the legacy `start_draft_timer`, `advance_draft_timer`, `complete_draft_timer`; create or replace everything in section 5, including the internal helpers and `_migration_report()`; revoke all API functions from `public`, `anon` and `authenticated` first and re-grant exactly the catalog.
- Report: the file ends with `select * from public._migration_report();`, so the SQL editor shows one row per open item (`severity`, `item`, `detail`, `action`: a `not valid` check, a skipped unique, a table missing from the publication, the bucket or its policy, a league without a usable pool) and no rows when nothing is left to fix. The function can be re-run at any time as the database owner (it is revoked from `anon` and `authenticated`); docs/schema.md, "Verifying the migration", lists every row kind.

Pool semantics: `leagues.custom_pool` (`{ version: "1.0", leagueName, pokemon: [{ name, points, tier }], source?: "format", draft_format_id? }`) is the only pool a league drafts from. `create_league` and `update_league_settings` copy the chosen format's list onto it at configuration time (`source: "format"`, `draft_format_id`) after `_validate_pool`; `update_league_pool` replaces it (no `source`); `reset_league_pool` copies the format again as it is right now; `reset_draft` keeps it; it is null only when no format was ever chosen or the format was removed from the settings. `draft_formats` is never read for a league's pool, so editing or deleting a format never changes what a league drafts from. The client reads `league.custom_pool?.pokemon ?? []` everywhere and reads `draft_formats` only for format names and to show the format behind a league.

## 5. RPC catalog

Conventions for every function:

- `language plpgsql security definer set search_path = public, extensions`; `revoke all on function ... from public, anon, authenticated; grant execute on function ... to authenticated;` (`get_server_time`, `get_invite_preview` and `is_league_member` are also granted to `anon`). Helpers prefixed with `_` have no API grants.
- The caller is `auth.uid()`; a null uid raises `not_authenticated`.
- Validation failures use `raise exception using message = '<user-facing sentence>', detail = '<snake_case_code>', errcode = 'P0001'` (`_fail`). The message is safe to display verbatim; `friendlyError()` shows it as is. Codes shared by many functions: `not_authenticated` (no user), `league_not_found`, `not_commissioner`, `not_a_member`.
- Row locks: every function that mutates a league first does `select ... from leagues where id = p_league_id for update` (`_lock_league`) so concurrent callers serialize.
- Internal helpers (not exported to the API): `_fail`, `_caller_uid`, `_lock_league`, `_league_commissioner_check(p_league_id)` (raises `not_commissioner`), `_member_for(p_league_id, uid)` (the caller's member row or `not_a_member`), `_validate_team_name`, `_visible_format`, `_validate_pool` (the pool contract: 1..2000 entries, unique non-empty trimmed names of at most 80 chars, integer points 1..20, `tier = 21 - points`; raises `invalid_pool` / `duplicate_pokemon` / `invalid_points` / `invalid_tier` naming the first offending entry; used by `update_league_pool`, `_format_pool` and the migration's format backfill), `_pool_rows` (a raw pokemon array as rows; lenient only for a list put on the row by hand: malformed entries skipped, duplicate names collapse to the most expensive entry), `_pool_json` (a league's pool as JSON: always `custom_pool`, never `draft_formats`), `_league_pool(p_league_id)` (the two combined: the effective pool as a set of (name text, points int, tier int)), `_format_pool` (a format as the `custom_pool` value that `create_league`, `update_league_settings` and `reset_league_pool` store, after `_validate_pool`; a failing format is refused with the same code and a message naming the format), `_positioned_members`, `_snake_member(p_league_id, p_pick_number)` (the on-clock member id), `_budget_fits` (the pure budget rule), `_pick_legal` (that rule for one candidate), `_best_available` (parses the pool once and applies the rule as a SQL filter, so auto-picks on a 2000-entry pool take milliseconds while the league row is locked), `_roster_total`, `_schedule_rows` (circle-method round robin, identical to `app/lib/league/schedule.ts`), `_new_invite_code`, `_create_invite`, `_setting_int`, `_advance_or_finalize`, `_finalize_draft`, `_pick_internal`, and `_migration_report` (section 4).

Schedule generation in SQL: build an ordered array of member ids (append a null "bye" when odd); for round r in 1..n-1 pair index i with n-1-i, skipping byes, alternating home/away per round; for double round robin append mirrored rounds with home and away swapped. Match numbers restart at 1 per round. The draft finalizes when the last pick number (`n * picks_per_team`) is consumed, whether by a pick or a skipped turn.

## 6. RLS policy set (complete)

All tables have RLS enabled. Only these policies exist after the hardening migration:

- `leagues`: select where `is_league_member(id)`; delete where `commissioner_id = auth.uid()`. No insert/update policies (functions only).
- `league_members`: select where `is_league_member(league_id)` (a `security definer` helper, so the policy does not evaluate itself recursively). No writes.
- `league_invites`: select where the caller is the league's commissioner. (Joiners go through `get_invite_preview`/`join_league`.)
- `draft_formats` (`authenticated` only): select where `created_by = auth.uid()`, or `created_by is null` (shared with everyone), or the row is the `draft_format_id` of a league the caller belongs to (`leagues.draft_format_id` + `is_league_member`, served by the `leagues(draft_format_id)` index), so the app can show the format behind a league through the `leagues -> draft_formats` embed; insert with check `created_by = auth.uid()`; update/delete where `created_by = auth.uid()` (no league is affected: each league holds its own copy in `custom_pool`). Column default `created_by uuid default auth.uid()`.
- `draft_picks`, `drafted_teams`, `league_matches`, `league_news`: select where `is_league_member(league_id)`. No writes.
- `draft_chat_messages`: select for league members; insert with check `user_id = auth.uid()` and a matching member row (existing policy, recreated). `id` and `created_at` are server-assigned by the `draft_chat_messages_defaults` trigger whatever the insert carries, so the room's `insert(...).select(...)` reads the stored values back.
- `pokemon_dex`, `pokemon_forms`: select for `authenticated`.
- `draft_order`: no policies (inaccessible).

The browser's only direct writes are `draft_formats` (own rows, from the Pool Builder), `draft_chat_messages` inserts (draft room) and `leagues` deletes (dashboard). PostgREST reports an update or delete that a policy filtered out as a success with zero rows, so those calls end with `.select("id").single()` (insert/update, turning the no-op into `PGRST116`) or `.select("id")` with an empty array treated as "no permission" (delete). Every other direct write to `leagues`, `league_members`, `league_invites`, `draft_picks`, `drafted_teams`, `league_matches` or `league_news`, and every call to a dropped or unknown RPC, is reported by `node scripts/check-client-contract.mjs` (exit 1), which `tests/db/client-contract.test.ts` also runs against the working tree.

## 7. Realtime

- Draft room (`useDraftRoom.ts`) subscribes on one channel (`league:<leagueId>:draft:<n>`, numbered by a module-level counter of its own) to `draft_picks`, `leagues`, `league_members` (filtered by league) and `draft_chat_messages` inserts, with a status callback: on `SUBSCRIBED` refetch; on `CHANNEL_ERROR`/`TIMED_OUT`/`CLOSED` show a "Reconnecting..." banner and fall back to polling every 10 s while the draft is active. Refetch on `visibilitychange` to visible. A dropped channel is announced once: the `DraftStatusBanner` (`role="status"`) carries it, while the Live pill in the page header and the explanatory notice under it are plain, non-live markup.
- Every client (not only the on-clock coach) calls `auto_pick_if_expired` once when its local timer reaches 0 and then every 5 s while it stays at 0.
- `loadDraft` carries a request generation counter; responses from stale generations are ignored. The overview, standings and pool pages pair the section 8.2 `active` flag with the same kind of counter, so a reload triggered by a realtime event or a Retry is never overwritten by a slower, older response.
- The other league pages share `useLeagueRealtime` (`app/(app)/leagues/[leagueId]/useLeagueRealtime.ts`): one channel per page, every listed table filtered by the league id (`id=eq.` for `leagues`, `league_id=eq.` elsewhere), a status callback that drives the Live / Connecting / Reconnecting pill (`LiveStatusPill`, a `role="status"` region) and refetches when the channel comes back, and `removeChannel` on unmount. Tables watched: overview `leagues`, `league_members`, `league_matches`, `league_news` (a `leagues` change calls the provider's `refresh()` so the phase card, coach list and invite seat count follow draft start, transfers and joins); standings `league_matches`, `league_members` (team renames); pool `leagues`; free agents `leagues`, `drafted_teams`, `league_news` (the `leagues` row too, so a changed swap limit or a draft reset shows without a manual refresh; the reset's `drafted_teams` deletes would not pass the league filter on their own); matches `league_matches`. The team page has no subscription.
- Every subscription uses a unique channel topic (`league:<id>:<page>:<n>`): supabase-js `channel(topic)` returns the existing channel for a repeated topic, and React's double-invoked development effects would otherwise re-attach to a channel that the first cleanup is still tearing down and never report "Live".

### 8.1 Shared modules

### 8.2 Data loading pattern

```ts
const supabase = useMemo(() => createClient(), []);
const load = useCallback(async () => { ... }, [supabase, leagueId]);
useEffect(() => {
  let active = true;
  void load().then(() => { if (!active) return; ... });
  return () => { active = false; };
}, [load]);
```

- Every page has `loading` state and renders skeletons; empty-state copy is gated on `!loading`.
- Every query destructures `error`; on error render an `Alert variant="error"` with a Retry button.
- Client code never treats `getUser()`'s `data.user === null` as "logged out": auth-js keeps the local session for a network failure, a 5xx or a rejected token, so `router.push("/login")` would only bounce back through the proxy. Use `getCurrentUser(supabase.auth)` (`app/lib/auth/current-user.ts`): `signed-in` carries `{ id, email }`; `signed-out` means auth-js has no local session (or has just cleared it for `session_not_found`), so `router.replace("/login")` is safe and the proxy agrees; `error` is rendered with `Alert variant="error"` and a Retry action while the session is kept. `tests/unit/auth-current-user.test.ts` covers the branches against the real auth-js client and lists the call sites (update-password, invite, dashboard, new league, builder).
- The dashboard, new-league and builder pages classify the session with `getCurrentUser` and, for `signed-out`, render a warning `Alert` with a "Log in" link (the new-league form also disables its submit button) instead of redirecting: the proxy already gates these routes, so a signed-out result there means the session vanished mid-visit. Inside a league the user comes from `useLeague()`; a league page never calls `getUser()` and never redirects.
- Pages that reload on realtime events or Retry keep a request-generation counter (`useRef`) next to the `active` flag so a stale response never overwrites a newer one (section 7).
- Success messages are set after the reload completes; loaders never clear messages.
- No `eslint-disable` comments for hooks rules; fix the dependency instead. The only `eslint-disable` in `app/` is the `@next/next/no-img-element` line in `PokemonSprite`. No `window.alert` and no `console.log`; `console.error` is used only by the error boundary and `friendlyError` (section 2: raw errors are logged, not displayed).

### 8.3 Forms and actions

- Inputs live in `<form onSubmit>`; buttons that mutate show a pending state and are disabled while pending.
- Numeric inputs parse with `Number.parseInt`, reject NaN, and clamp to the ranges in section 4 before calling the RPC; the RPC re-validates.
- Destructive actions (delete league, reset draft, regenerate schedule with results, undo move, remove member) use `Dialog` with a typed confirmation where the current app already does (league name) or an explicit confirm button otherwise.
- The overview news feed offers Undo only on each team's newest `free_agent` row among the loaded rows (`undoableNewsIds` in `NewsFeed.tsx`); `undo_free_agent_move` still validates every call and its message is shown inside the dialog. Regenerating an invite uses the same `Dialog danger` on the overview and on Settings (title "Regenerate invite link?", confirm "Regenerate link", description saying the old link stops working); the Settings card hides the link and its buttons once the draft has started, since `join_league` refuses new coaches from then on.
- A league delete that returns zero rows (the league is already gone, or the caller is no longer its commissioner) closes the dialog, reloads the list and shows a warning banner instead of an error inside the dialog.
- The draft-order Move up / Move down buttons stay rendered, disabled, at the ends of the list; after a move, focus goes back to the pressed button or, when that button is disabled now, to its sibling (React relocates the moved row's DOM node, which would otherwise drop focus to the body).
- Password recovery keeps `next` (the page the user was heading for, e.g. an invite) across the whole round trip: both "Forgot your password?" links on the login form are `withNextParam("/forgot-password", next)`; `forgot-password/page.tsx` reads `next` from `searchParams` through `sanitizeNextPath` and the form sends `redirectTo = <origin>/auth/callback?next=<encoded withNextParam("/update-password", next)>`, i.e. `/update-password?next=<path>` (plain `/update-password` for the default destination); the callback route unwraps and re-validates it with `resolveCallbackNext`; `update-password/page.tsx` sanitizes `next` again (and refuses `/update-password` itself) and the form runs `router.replace(next)` after `updateUser({ password })` instead of always going to `/dashboard`. The logged-out state's "Request a new link" and the standing "Back to log in" link carry `next` too. `tests/unit/shared-ui-review.test.ts` replays the encoded value through `resolveCallbackNext` for both the PKCE `?code` and the token-hash `next={{ .RedirectTo }}` link shapes.
- The browser's only direct writes are the ones section 6 allows: `draft_formats` in the Pool Builder (insert with `.select("id").single()`, update/delete with `.eq("id", ...).select("id")`, `created_by` never sent), `draft_chat_messages` inserts in the draft room, and the league delete on the dashboard (`.delete().eq("id", id).select("id")`, an empty result treated as "nothing deleted / no permission"). Everything else goes through `rpc.*`; after any mutation that changes the league or member row the page calls `refresh()` from `useLeague()`. The Pool page re-reads `leagues.custom_pool` before saving and refuses to overwrite a pool that changed since editing began (the RPC itself is last-writer-wins).

### 8.4 Accessibility

- Every control has a label (`Field`) or `aria-label`; tables use `scope="col"`; navs have `aria-label`; active nav link has `aria-current`; toggle buttons expose `aria-pressed`; the draft timer region is `aria-live="off"` with a separate `role="status"` banner announcing "You are on the clock"; dialogs trap focus and restore it. `LiveStatusPill` (`app/(app)/leagues/[leagueId]/LiveStatusPill.tsx`, the `role="status"` pill shared by the overview news feed, standings, pool, free-agent and matches pages) puts a visually hidden `Live updates: ` prefix before its label inside the region, so a state change is announced as "Live updates: Reconnecting" rather than a bare "Reconnecting" (a live region reads its changed content, so the subject has to be content, not an `aria-label`); it is the same prefix the draft room's `LivePill` uses, and the visible pill text stays the bare word. `tests/unit/shared-ui-review.test.ts` asserts both.
- Buttons whose visible text repeats on every row (Delete on the dashboard; Make commissioner, Remove and Leave league on the coaches lists; Add on the free-agent list; Remove on the pool; the "<team> won" result buttons on the Matches page, whose two spans would otherwise concatenate to "Coach Twowon") carry an `aria-label` that contains the visible text and names the row, e.g. `Delete <league name>`, `Make commissioner: <team>`, so the visible label stays part of the accessible name (WCAG 2.5.3). `tests/unit/league-pages-review.test.ts` checks this for the league pages.
- Landmarks: the signed-in shell is `AppNav` + `<main id="main-content">`; the landing page (`app/page.tsx`) renders its `<header>` and `<footer>` as siblings of `<main id="main-content">`, not inside it, so they are exposed as the banner and contentinfo landmarks.
- Inline text links (the auth pages' "Forgot your password?", "Sign up", "Log in", "Back to log in", "request a new one", the auth layout's brand link and the landing footer links) use `linkClassName` from `app/lib/theme` (`rounded focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-focus focus-visible:ring-offset-2 focus-visible:ring-offset-bg`, the Button ring) plus their own colour classes, never a bare `hover:underline` with the browser outline. `tests/unit/shared-ui-review.test.ts` checks every `<Link>` in those files.
- Theme picker uses a native `<select>` styled to match; below `sm` it is a 40px icon-only control (palette icon + accent swatch, transparent value text, hidden chevron) so the AppNav fits a 320px viewport.
- Focus indicators use the opaque per-theme `--color-focus` token (`focus-visible:ring-2 focus-visible:ring-focus`; inputs use `focus:border-focus focus:ring-1 focus:ring-focus`), never the translucent `accent-border`, so the ring is at least 3:1 against `bg`, `panel` and `panel-hover` in every palette (WCAG 1.4.11). `tests/unit/theme-contrast.test.ts` asserts this.
- Unfocused text fields and selects (`Input`, `Select`, `NumberInput`, the ThemeToggle `<select>`) draw their boundary with the opaque per-theme `--color-control-border` token, which is at least 3:1 against `bg` (the field fill), `panel` and `panel-hover` in every palette (WCAG 1.4.11); the translucent `border-line` is only for decorative card and divider lines. `tests/unit/ui-a11y-review.test.ts` asserts this.
- `TypeBadge` applies the canonical type colours (`pokemonTypeColours` in `app/lib/theme`) as inline styles rather than palette utilities, so no theme recolours them; a Grass badge is green in every theme. These two files are the only inline colour styles in the app. The root layout exports `generateViewport` (not a static `viewport`): it reads the theme cookie like the layout body does and sets `themeColor` to `themeBackgrounds[theme]` (the palette's `--type-bg`) so the mobile browser chrome matches the page background; that is a `<meta>` value, not a class. It is re-resolved per request, and `ThemeProvider.setTheme` also writes the same `themeBackgrounds` value into the rendered `<meta name="theme-color">`, so a theme change made with the picker reaches the chrome immediately as well as on the next navigation or refresh.

## 12. Standings tiebreakers and playoffs

Same rules as the rest of this document: every mutation is a Postgres function, the client never writes the tables, and the migration `supabase/migrations/20260912120000_playoffs.sql` is idempotent and applies both to a fresh project and on top of the existing one. ### 12.1 Glossary additions

| Term | Meaning | Use in UI |
| --- | --- | --- |
| Regular season | The round-robin schedule (`league_matches.stage = 'regular'`) | "Regular season" |
| Playoffs | The single-elimination bracket after the regular season (`stage = 'playoff'`) | "Playoffs", "Playoff bracket" |
| Seed | A coach's final regular-season position, 1 = best | "Seed 1", "#1 seed" |
| Differential | Total Pokémon left standing in wins minus Pokémon the opponent had left in losses | "Diff" in tables, "differential" in prose |
| Strength of schedule | Average regular-season win percentage of a coach's opponents | "Strength of schedule" |

### 12.2 Data model

New columns (all added with `if not exists`, constraints via the same guarded helpers as the hardening migration):

- `leagues.tiebreaker text not null default 'head_to_head'`, check in `('head_to_head', 'differential')`: which tiebreaker applies first.
- `leagues.playoff_format text not null default 'none'`, check in `('none', 'top_2', 'top_4', 'top_6', 'top_8')` (the column default keeps existing leagues as they were; `create_league` defaults new ones to `top_4`).
- `leagues.champion_member_id uuid null references league_members(id) on delete set null`.
  This is a second foreign key between the two tables, so PostgREST embeds between `leagues` and `league_members` must carry a column hint (`leagues!league_id(...)` on the dashboard); an unhinted embed fails with HTTP 300. `tests/unit/postgrest-embeds.test.ts` enforces it.
- `league_matches.stage text not null default 'regular'`, check in `('regular', 'playoff')`.
- `league_matches.winner_remaining integer null`, check between 1 and 12: Pokémon the winner had left standing (null when not recorded; counts as 0 in the differential).
- `league_matches.home_seed integer null`, `away_seed integer null`: playoff seeds for display.
- `league_matches.feeds_match_id uuid null references league_matches(id) on delete set null`, `feeds_slot text null` check in `('home', 'away')`: where the winner advances.
- `league_matches.home_member_id` and `away_member_id` become nullable (a playoff slot not yet decided). Every existing constraint stays: playoff rounds continue `round_number` after the last regular round, so `(league_id, round_number, match_number)` remains unique.
- `league_news.news_type` check extended to `('free_agent', 'match_result', 'season')`.
- Data fix: leagues with `playoff_format = 'none'`, `draft_completed`, at least one regular match, every regular match completed, no bracket and no champion yet get `champion_member_id = seed 1` from the standings (a `notice` says how many); leagues that already carry a champion are left alone, so re-running the file changes nothing.
- Before the checks are added, values outside the new sets in `tiebreaker`, `playoff_format` and `stage` (only possible when a column was added by hand first) fall back to the defaults, the way the hardening file clamps; the `winner_remaining` and `feeds_slot` checks rely on the guarded helper's `NOT VALID` fallback. Any existing check on `league_news.news_type` that does not allow `season` is replaced, whatever its name.
- Two partial indexes: `league_matches(feeds_match_id) where feeds_match_id is not null` (the self-referencing foreign key's `on delete set null` would otherwise scan the table once per deleted match when a schedule is regenerated) and `leagues(champion_member_id) where champion_member_id is not null`.

Playoff rounds are numbered `last_regular_round + 1 ..`. Round display names come from the distance to the final, not from the number of matches on file: the last playoff round is the Final, the one before it the Semifinals, the one before that the Quarterfinals (`_round_name(rounds_from_final)` in SQL, `playoffRoundName(2 ** (lastPlayoffRound - round_number))` on the client), so the two-match first round of a `top_6` bracket is the Quarterfinals in the bracket headings and in the news text alike.

### 12.3 Standings algorithm (one definition, two implementations)

Implemented in SQL as `league_standings(p_league_id)` and mirrored by `computeStandings` in `app/lib/league/standings.ts`; `tests/db/playoffs.test.ts` runs both on randomised fixtures and requires identical output. Only `stage = 'regular'` matches with `status = 'completed'` and a winner count.

1. Order by win percentage desc, then wins desc.
2. Groups still tied on both are ordered by the tiebreakers in this order: the league's primary tiebreaker, then the other one, then strength of schedule, then the coin flip.
   - Head-to-head: within the tied group, win percentage in completed regular matches between group members (0 when a coach has none); higher first. After applying it, sub-groups that are still tied continue with the next tiebreaker.
   - Differential: sum over completed regular matches of `+winner_remaining` for wins and `-winner_remaining` for losses (null counts 0); higher first.
   - Strength of schedule: mean win percentage of the opponents faced in completed regular matches, one term per match so a repeated opponent counts twice (0 when none); higher first.
   - Coin flip: `league_members.id` ascending. It is deterministic so seeding never changes between calls; the UI calls it a coin flip.
3. Output per coach: `member_id`, `seed` (1..n, always distinct), `rank` (shared by coaches separated only by the coin flip), `tied` (true when separated only by the coin flip), `wins`, `losses`, `played`, `remaining`, `win_pct` (numeric, 3 decimals), `differential`, `strength_of_schedule` (numeric, 3 decimals), `head_to_head_applied` (boolean: true for every coach of a head-to-head group whose records were not all equal, i.e. whose position depended on that comparison).

Percentages (win, head-to-head, strength of schedule) are compared rounded to 3 decimals, half up, the precision the function returns and the table shows, so two coaches never differ only in a digit nobody sees: 10-17 (.370) and 17-29 (.370) tie on percentage and wins decide; two strength-of-schedule means that both print as .708 leave the coin flip to decide. `computeStandings` rounds the same way (`roundPercentage`), and the parity test holds both to fixtures on rounding boundaries (0.3125 rounds up to .313 on both sides).

`league_standings` is `security definer`, granted to `authenticated`, raises `league_not_found` for an unknown league id and `not_a_member` unless the caller is in the league. Members whose `draft_position` is null and who appear in no match are excluded, by both implementations themselves. The standings page, the overview status card and the bracket generator call it; the matches page labels bracket slots from the `home_seed`/`away_seed` the generator stored, so it needs no second call.

### 12.4 Bracket shapes

Single elimination, seeded from `league_standings`, higher seed is home, no reseeding between rounds. Generated all at once with undecided slots null.

- `top_2`: Final: 1 v 2.
- `top_4`: Semifinals: M1 = 1 v 4, M2 = 2 v 3. Final: winner M1 v winner M2.
- `top_6`: Quarterfinals: M1 = 4 v 5, M2 = 3 v 6 (seeds 1 and 2 have a bye). Semifinals: M1 = 1 v winner QF1, M2 = 2 v winner QF2. Final.
- `top_8`: Quarterfinals: M1 = 1 v 8, M2 = 4 v 5, M3 = 3 v 6, M4 = 2 v 7. Semifinals: M1 = winner QF1 v winner QF2, M2 = winner QF3 v winner QF4. Final.

`feeds_match_id` and `feeds_slot` point each match at the slot its winner fills; the final has neither. A playoff match with a null participant is "waiting" and cannot be reported (`match_not_ready`). The client derives "Winner of Quarterfinal 2" for an empty slot from the match whose `feeds_match_id` is this match and whose `feeds_slot` is the empty side.

## 13. Pool Builder v2: the Pokémon dataset, games, regulation presets and rule-built pools

Added 2026-09-16. Everything in this section is binding for the feature; earlier sections stay as they are unless a line here says otherwise. The league-side pool contract does not change: a pool entry that reaches a league is still exactly `{ name, points, tier }` (section 8.1, `_validate_pool`). What changes is where the builder gets its Pokémon from and how it decides which ones go in.

### 13.1 Goals and decisions

- A pool can be built from a **source** (one or more games, or every Pokémon), an optional **regulation preset**, and **filters** (base stats, generation, types, categories, form kinds), then **priced** by stat total with editable bands, then tweaked by hand exactly as today.
- Games at launch: **Pokémon Champions**, **Pokémon Scarlet and Violet**, and **All Pokémon** (every distinct Pokémon that exists, for leagues played on Pokémon Showdown). The dataset carries every game PokéAPI knows so adding a checkbox later is a one-line change.
- Forms: **regional forms** (Alolan, Galarian, Hisuian, Paldean) and **gender forms that are different Pokémon** (Meowstic, Indeedee, Basculegion, Oinkologne) are separate entries and included by default; **Mega Evolutions** are separate entries behind a toggle that defaults on; **other battle-relevant forms** (Rotom appliances, Toxtricity Low Key, Urshifu styles, Ogerpon masks, Origin, Therian, Crowned, riders, and so on) are separate entries and included by default. Cosmetic variants (Vivillon patterns, Pikachu caps, Alcremie flavours, totems) and in-battle-only transformations (Gigantamax, Zen Mode, Blade, School, Ash-Greninja, Terastal forms) are never entries.
- Presets at launch: Champions **Regulation Set M-A, M-B, M-C** (rosters) and Scarlet/Violet **Regulation Set A through I** (rules). Presets are data, not code, so a new regulation is a data change plus a rebuild.
- Rules are saved with the format, so a format can be rebuilt from its rules after the dataset is refreshed.

### 13.2 Glossary additions

| Term | Meaning | UI label |
| --- | --- | --- |
| Dataset | The `pokemon` table: one row per distinct, usable Pokémon with stats, types, tags and game availability | "Pokémon" |
| Entry / form kind | `default`, `mega`, `regional`, `gender`, `other`; the row's relation to its species | "Form" |
| Game | A game key the dataset knows availability for (`champions`, `scarlet_violet`, and the others in 13.4) | the game's name |
| Source | What the builder starts from: a set of games or All Pokémon | "Start from" |
| Preset | A regulation set: a roster or a filter rule with a name, dates and a source link | "Regulation" |
| Tag | A category on a row: `legendary`, `sub_legendary`, `restricted`, `mythical`, `paradox`, `ultra_beast` | "Categories" |
| Stat total | Sum of the six base stats (`bst`) | "Stat total" |
| Rules | The saved recipe of a format: source, preset, filters, form toggles, pricing bands | "Rules" |
| Bands | The stat-total thresholds that map to points 1..20 | "Price by stat total" |

### 13.3 Data sources and the build script

The dataset is generated, never typed. `scripts/build-pokemon-data.mjs` (Node, no dependencies beyond the repo's) produces the committed files under `data/pokemon/` from:

- **PokéAPI** (`https://pokeapi.co/api/v2`): `pokemon-species/1..1025`, every `pokemon` variety those species list, every `pokemon-form` those varieties list, every `pokedex`, `version-group` and `generation`. Raw responses are cached under `POKEAPI_CACHE_DIR` (default `scripts/.cache/pokeapi/`, git-ignored); a rerun only fetches what is missing. Requests carry a descriptive `User-Agent` (PokéAPI returns 403 without one), run at most 6 in parallel, and retry with backoff. A full cold crawl is about 4,000 requests and takes under two minutes.
- **Serebii regulation pages** for Champions rosters: `https://www.serebii.net/pokemonchampions/rankedbattle/regulationm-{a,b,c}.shtml`. Each roster row is an anchor `<a href="/pokedex-champions/<slug>/">Name<br />Japanese</a>` preceded by an icon `/pokedex-champions/icon/<dex>[-<suffix>].png`; the suffix names the form (`a` Alolan, `g` Galarian, `h` Hisuian, `p` Paldean, `m` Mega, `mx`/`my` Mega X/Y, other suffixes such as `b`/`e` are breed or form markers resolved by the parser's suffix table, and an unknown suffix fails the build). M-A's page carries the launch roster; M-B and M-C carry the additions, so a regulation's roster is cumulative: M-B = M-A plus M-B's list, M-C = M-B plus M-C's list. A row without an icon suffix names the species, and Serebii only draws a form icon for forms with a Champions Pokédex page of their own, so the roster also takes every `other` and `gender` row of that species that carries `champions` (Rotom appliances, Lycanroc Dusk and Midnight, Gourgeist sizes, Meowstic (Female), Basculegion (Female)); when the same species' default Mega is also named (the `m` icon), the Megas of those forms that carry `champions` join too (Mega Meowstic (Female)). Regional forms and any other Mega only join when Serebii's icon names them. Plain Floette is the one `champions` row on no roster, because Serebii lists only Eternal Flower Floette and Mega Floette; the integrity test pins that. The parsed rows are committed as `data/pokemon/sources/serebii-m-a.json` (and `-b`, `-c`) with `{ dex, slug, name, suffix }`; the script reads the saved pages under `scripts/.cache/serebii/` when present, else the committed sources, and re-fetches them only with `--refresh-serebii`, so the build does not depend on Serebii being up.
- **Curated overrides** in `data/pokemon/overrides.json` (hand-maintained, reviewed in pull requests): tag lists PokéAPI does not carry (`paradox`, `ultra_beast`, `restricted`), a `keep` list of varieties exempted from rule 2's battle-only skip with the reason (Crowned Zacian and Zamazenta, which PokéAPI flags battle-only but 13.1 lists as included forms), display-name fixes, extra game availability (for example the Reg M-C additions PokéAPI lists in its `champions` Pokédex but has no Champions learnsets for yet, and their new Megas), and whole rows for Pokémon PokéAPI lacks. An override names a row by `slug` and may set any dataset column (`games` and `tags` are added to the built values, any other column replaces it); a row whose slug PokéAPI does not know must give every column.

The script writes:

- `data/pokemon/pokemon.json`: the dataset rows (13.4), sorted by `species_id` then `id`.
- `data/pokemon/regulations.json`: the presets (13.6), rosters resolved to dataset `slug`s.
- `data/pokemon/report.json`: counts per game, per form kind, per tag, per preset, and the list of roster names it could not map. **An unmapped roster name or an unknown icon suffix fails the script** (exit 1); a preset whose count moved by more than 20% from the committed report prints a warning.

Rules the script applies, in this order, to decide which PokéAPI `pokemon` varieties become rows:

1. Every species' default variety is a row (`form_kind = 'default'`).
2. A variety whose `pokemon-form` has `is_battle_only` is skipped, unless it is a Mega Evolution or Primal Reversion (PokéAPI flags every one of those battle-only, and without the exemption no `mega` row would reach rule 3) or the overrides' `keep` list names it (Crowned Zacian and Zamazenta); so is any variety whose slug ends in `-gmax`, `-eternamax` (Eternatus's Dynamax form, which PokéAPI does not flag battle-only), `-totem`, or names a cosmetic Pikachu (`-cosplay`, `-rock-star`, `-belle`, `-pop-star`, `-phd`, `-libre`, `-original-cap`, `-hoenn-cap`, `-sinnoh-cap`, `-unova-cap`, `-kalos-cap`, `-alola-cap`, `-partner-cap`, `-world-cap`, `-starter`), or `eevee-starter`.
3. A variety whose `pokemon-form` has `is_mega`, or whose slug ends in `-primal`, is a `mega` row (Primal Groudon and Primal Kyogre are `mega` rows with `form_label` "Primal", as 13.4's naming assumes).
4. A variety whose slug carries `-alola`, `-galar`, `-hisui` or `-paldea` (including the Paldean Tauros breeds) is a `regional` row.
5. A variety whose slug ends in `-female` or `-male` is a `gender` row.
6. Any other variety whose stats, types **or abilities** differ from its species' default variety is an `other` row (this keeps Meowstic-F, whose stats match but abilities differ, and drops cosmetic varieties such as Vivillon patterns, Flabébé colours, Alcremie flavours, Furfrou trims, Unown letters, Sinistea Antique, Magearna Original, Zarude Dada, Xerneas Active).
7. Anything else is skipped. A variety that passes rule 3 or 6 but whose stats, types and abilities equal a variety of its species that is already a row is a cosmetic duplicate and is skipped too, with the report naming the row it duplicates (`sameAs`): the six other Minior colour cores duplicate Minior (Core), Squawkabilly White Plumage duplicates Yellow Plumage, and the Megas of cosmetic varieties duplicate the kept variety's Mega (Droopy and Stretchy Mega Tatsugiri, Mega Magearna Original). A Mega whose own base variety is a row is kept even when its data matches another Mega, so Mega Meowstic (Female) stays. (Rule 6 alone cannot deliver its Minior example: every Minior core differs from the default Meteor form, which is why the duplicate clause exists.) The report lists every skipped variety with the reason so a wrong skip is visible in review.

Expected sizes from the 2026-09-16 crawl (`EXPECTED_KIND_COUNTS` in `scripts/lib/pokemon-data/rows.mjs`; the build and the integrity test assert within 5%): 1025 default, 96 mega (PokéAPI's 97 `is_mega` forms plus the two Primal Reversions, minus the three duplicate Megas of rule 7), 57 regional (the crawl's 59 count `pikachu-alola-cap` and `darmanitan-galar-zen`, which rule 2 drops first), 4 gender, 55 other (63 by rules 1 to 6, minus the seven duplicates of rule 7 and Eternamax); 1,237 rows in total.

### 13.4 The dataset table

Migration `supabase/migrations/20260916120000_pool_builder.sql`, after the playoffs file, idempotent like the others:

```sql
create table if not exists public.pokemon (
  id integer primary key,                      -- PokéAPI pokemon id, stable
  species_id integer not null,                 -- national dex number
  slug text not null unique,                   -- PokéAPI pokemon name, e.g. 'charizard-mega-x'
  display_name text not null unique,           -- app convention, e.g. 'Mega Charizard X'
  species_name text not null,                  -- 'Charizard'
  form_kind text not null check (form_kind in ('default','mega','regional','gender','other')),
  form_label text,                             -- 'Mega X', 'Alolan', 'Wash', 'Female'; null for default
  type1 text not null,
  type2 text,
  hp smallint not null, attack smallint not null, defense smallint not null,
  special_attack smallint not null, special_defense smallint not null, speed smallint not null,
  bst smallint generated always as (hp + attack + defense + special_attack + special_defense + speed) stored,
  generation smallint not null check (generation between 1 and 9),
  tags text[] not null default '{}',
  games text[] not null default '{}',
  dex_numbers jsonb not null default '{}',     -- { "paldea": 12, "champions": 6, ... }
  sprite_url text,
  updated_at timestamptz not null default now()
);
```

- Types are the capitalised app spelling used by `pokemon_dex` and `TYPE_OVERRIDES` ("Fire", "Flying").
- `tags`: `legendary` (PokéAPI `is_legendary`, which includes sub-legendaries), `mythical` (`is_mythical`), `restricted` (curated: the Regulation I restricted list, 31 entries with forms, applied to every form of those species), `sub_legendary` (`legendary` and not `restricted`), `paradox` (curated, 20 species), `ultra_beast` (curated, 11 species). Forms inherit their species' tags.
- `games`: a row is available in a game when it has a learnset for one of the game's version groups, or its species is in one of the game's Pokédexes and the row is the default form, or an override says so. Game keys and their PokéAPI sources: `champions` (version group `champions`, Pokédex `champions`), `scarlet_violet` (`scarlet-violet`, `the-teal-mask`, `the-indigo-disk`; Pokédexes `paldea`, `kitakami`, `blueberry`), `legends_za` (`legends-za`, `mega-dimension`; `lumiose-city`, `hyperspace`), `sword_shield` (`sword-shield`, `the-isle-of-armor`, `the-crown-tundra`; `galar`, `isle-of-armor`, `crown-tundra`), `legends_arceus` (`hisui`), `bdsp` (`original-sinnoh`, the 151-entry dex PokéAPI files `brilliant-diamond-shining-pearl` under; `extended-sinnoh` is Platinum's), `lets_go` (`letsgo-kanto`), `ultra_sun_ultra_moon` (`updated-alola`), `sun_moon` (`original-alola`), `oras` (`updated-hoenn`), `x_y` (the three Kalos dexes), plus one key per older generation's main pair (`black_2_white_2`, `black_white`, `heartgold_soulsilver`, `platinum`, `diamond_pearl`, `emerald`, `firered_leafgreen`, `ruby_sapphire`, `crystal`, `gold_silver`, `yellow`, `red_blue`; `GameKey` in `app/types/pokemon.ts` and `GAMES` in `scripts/lib/pokemon-data/games.mjs` spell them identically). Only `champions`, `scarlet_violet` and All Pokémon get a control in the builder at launch.
- `dex_numbers`: entry numbers per Pokédex for the species, used by the Scarlet/Violet Reg A to C rules.
- `display_name` follows the app's existing prose convention so every current lookup keeps working: regional forms `Alolan Raichu`, `Galarian Mr. Mime`, `Hisuian Zoroark`, `Paldean Wooper`, and the three Paldean Tauros breeds spelled alike, `Paldean Tauros (Combat Breed)`, `Paldean Tauros (Blaze Breed)`, `Paldean Tauros (Aqua Breed)` (the legacy spelling `Paldean Tauros` that leagues may store resolves to the Combat Breed row through `toPokeApiSlug`); megas `Mega Venusaur`, `Mega Charizard X`, Legends Z-A's `Mega Absol Z`, and `Mega Meowstic` / `Mega Meowstic (Female)` for the megas of a gendered species; primal `Primal Groudon`; gender `Indeedee (Female)`; every other form `Species (Form)` with the form's English name, `Rotom (Wash)`, `Toxtricity (Low Key)`, `Urshifu (Rapid Strike)`, `Ogerpon (Wellspring Mask)`, `Calyrex (Shadow Rider)`, `Giratina (Origin)`, `Zacian (Crowned Sword)`, `Floette (Eternal Flower)`, `Minior (Core)`. `normalizePokemonName("Rotom (Wash)")` equals `normalizePokemonName("rotom-wash")`, which is why the parenthesised prose is the convention; every regional and mega display name also round-trips through `toPokeApiSlug` (`SPECIAL_SLUGS` knows the Z megas, the breeds and `meowstic-male-mega` / `tatsugiri-curly-mega`). Where `TYPE_OVERRIDES` or an existing format already uses a different spelling for a form, the override file fixes the display name so the dataset agrees with what leagues already store.
- `sprite_url`: PokéAPI's official artwork (`sprites.other["official-artwork"].front_default`), falling back to `front_default`, then to the species row's sprite. The app renders sprites with a plain `img`, so no image host configuration changes.
- RLS: `select` for `authenticated` only (same as `pokemon_dex`); no client writes; no policies for anon. Indexes: `(species_id)`, `(bst)`, GIN on `tags` and on `games`. Grants section lists the table for the contract script. `pokemon_dex` and `pokemon_forms` stay untouched in this release; the dataset replaces their reads (13.7) and a later cleanup drops them.

Seeding: `scripts/seed-pokemon.ts` (`npm run seed:pokemon`) validates every row of `data/pokemon/pokemon.json` against the table's constraints, parks the rows whose `slug` or `display_name` the file moved to another `id` (both are unique and checked row by row, so a swap or a move would otherwise fail with `23505`), upserts every row on `id` into `public.pokemon` with the service-role key from `.env.scripts` (the only file the scripts read, section 10 step 3) in batches of 500, then deletes rows whose `id` is not in the file, and prints the counts. It is the only writer. The DB suite inserts the same file into embedded Postgres to prove the file satisfies the constraints (the test cluster is initialised `UTF8` like Supabase, so Nidoran♀ and ♂ insert).

### 13.5 The rules of a format

`draft_formats.json` gains an optional `rules` object next to `version`, `leagueName` and `pokemon` (the check constraint only validates `pokemon`, so no migration is needed for it, and `_format_pool` still copies only the list into a league):

```jsonc
{
  "version": "2.0",
  "source": { "kind": "games", "games": ["champions"] } | { "kind": "all" },
  "preset": "champions-m-c" | null,
  "filters": {
    "bst": { "min": null, "max": 600 },
    "stats": { "hp": null, "attack": null, "defense": null, "special_attack": null, "special_defense": null, "speed": 100 },  // per-stat maximums
    "generation": { "min": null, "max": null },
    "types": [],                                   // empty = any; otherwise the row's type1 or type2 must be listed
    "excludeTags": ["mythical"],                   // any of the six tags
    "forms": { "mega": true, "regional": true, "gender": true, "other": true }
  },
  "pricing": { "mode": "bands", "bands": [700, 680, 650, 620, 600, 580, 560, 540, 520, 500, 480, 460, 440, 420, 400, 380, 350, 320, 280, 0] } | { "mode": "manual" }
}
```

- The block above is the `rules` object itself: `rules.version` is `"2.0"` (`RULES_VERSION`), while the format's own `version` stays `"1.0"` (`POOL_VERSION`), so a league or an older client that reads `version` sees nothing new.
- `bands` has exactly 20 descending integers: entry `i` is the minimum stat total for `20 - i` points, and the last entry is 0 so every Pokémon gets at least 1 point. The default bands above are the starting values; the builder shows them as an editable table.
- Applying rules (`app/lib/pokemon/rules.ts`, pure and unit-tested): start from the dataset rows in the source; a preset with a roster intersects with the roster, a preset with a filter rule applies that rule first (13.6); then the format's own filters; the result is sorted by stat total descending then display name. Pricing in bands mode maps each row's `bst` to points; `tier = 21 - points` as everywhere else.
- A format saved from the builder always carries `rules` (with `pricing.mode = "manual"` once the user edits a price by hand and chooses to keep manual prices). Formats without `rules` (every existing one) load and behave exactly as today.

### 13.6 Presets

`data/pokemon/regulations.json` is an array of:

```jsonc
{ "key": "champions-m-c", "game": "champions", "name": "Regulation Set M-C", "starts": "2026-09-09", "ends": "2026-12-02",
  "source": "https://www.serebii.net/pokemonchampions/rankedbattle/regulationm-c.shtml",
  "rule": { "kind": "roster", "slugs": ["venusaur", "venusaur-mega", ...] },
  "notes": "Megas allowed. Species and item clauses." }
```

or a filter rule:

```jsonc
{ "key": "sv-reg-h", "game": "scarlet_violet", "name": "Regulation Set H", "starts": "2024-09-01", "ends": "2025-01-05",
  "source": "https://www.serebii.net/scarletviolet/rankedbattle/regulationh.shtml",
  "rule": { "kind": "filter", "dexes": null, "dexRanges": null, "excludeTags": ["legendary", "mythical", "paradox"], "restrictedPerTeam": 0 } }
```

Filter-rule fields: `dexes` limits the species to those Pokédexes (null = every row available in the game, which for Scarlet/Violet means HOME transfers too); `dexRanges` limits Paldea entry numbers (`{ "paldea": [[1, 375], [388, 392]] }`); `excludeTags` removes rows carrying any listed tag; `restrictedPerTeam` is informational (a draft league drafts the Pokémon; the number is shown in the preset description). The Scarlet/Violet presets:

| Key | Eligible | Rule |
| --- | --- | --- |
| `sv-reg-a` | Paldea dex 1-375 and 388-392 | `dexes: ["paldea"]`, `dexRanges`, `excludeTags: ["paradox", "legendary", "mythical"]` |
| `sv-reg-b` | Paldea dex, Paradox allowed | `dexes: ["paldea"]`, `excludeTags: ["legendary", "mythical"]` |
| `sv-reg-c` | Paldea dex, Treasures of Ruin allowed | `dexes: ["paldea"]`, `excludeTags: ["restricted", "mythical"]` |
| `sv-reg-d` | Everything transferable, sub-legendaries allowed | `dexes: null`, `excludeTags: ["restricted", "mythical"]` |
| `sv-reg-e` | Paldea and Kitakami dexes | `dexes: ["paldea", "kitakami"]`, `excludeTags: ["restricted", "mythical"]` |
| `sv-reg-f` | Paldea, Kitakami and Blueberry dexes | `dexes: ["paldea", "kitakami", "blueberry"]`, `excludeTags: ["restricted", "mythical"]` |
| `sv-reg-g` | Everything transferable, one restricted per team | `dexes: null`, `excludeTags: ["mythical"]`, `restrictedPerTeam: 1` |
| `sv-reg-h` | Everything transferable, no legendaries, mythicals or Paradox | `dexes: null`, `excludeTags: ["legendary", "mythical", "paradox"]` |
| `sv-reg-i` | Everything transferable, two restricted per team | `dexes: null`, `excludeTags: ["mythical"]`, `restrictedPerTeam: 2` |

The build script derives Reg A, B and C twice, by ranges and by tags, and fails if the two disagree, which catches a wrong tag list. Dates and sources for the SV sets come from Victory Road's rules page and Serebii; the Champions dates are M-A 2026-04-08 to 06-17, M-B 06-17 to 09-09, M-C 09-09 to 12-02.

### 13.7 Client

- **Dex loading** (`app/lib/pokemon/index.ts`): `loadDex()` reads `public.pokemon` (`display_name, slug, sprite_url, type1, type2`) instead of `pokemon_dex`, keyed by the normalized `display_name` **and** the normalized `slug`, and falls back to `pokemon_dex` only when the table is empty (a project that has not run the seed yet). `DexEntry` is unchanged, so the draft room, team, free-agent, pool and matches pages keep resolving types and sprites by name, now for every form. `TYPE_OVERRIDES` stays as the last fallback. `useDex` is unchanged.
- **Dataset loading** (`app/lib/pokemon/dataset.ts`): `loadDataset()` reads every `pokemon` row once per session (paginated like the dex) into `PokemonEntry[]` (`app/types/pokemon.ts`: the columns of 13.4, `tags` and `games` as string arrays). A table that does not exist yet (PGRST205 / 42P01, the migration not applied) is returned as an empty dataset, the same as an unseeded table, so the builder shows its empty state rather than an error during the window between deploying the client and applying the migration; any other error is thrown. Only the builder calls it.
- **Rule engine** (`app/lib/pokemon/rules.ts`): `applyRules(entries, presets, rules)`, `priceByBands(bst, bands)`, `defaultRules(source)`, `describePreset(preset)`, `GAME_LABELS`, `TAG_LABELS`, `FORM_KIND_LABELS`, `DEFAULT_BANDS`. Pure, no React.
- **Builder page** (`app/(app)/builder/`): a new `RuleBuilder.tsx` card above the existing pool table, with:
  1. **Start from**: a radio between "Games" (checkboxes: Pokémon Champions, Scarlet and Violet) and "All Pokémon"; at least one game when "Games" is chosen.
  2. **Regulation**: a select of the presets for the chosen games plus "None"; the description under it shows the dates, the rule in words ("Paldea and Kitakami Pokédexes, no restricted or mythical Pokémon") and the source link. Choosing a preset sets its game and leaves the filters as they are.
  3. **Filters**: stat total min and max, six per-stat maximum inputs, generation min and max, a type multi-select, category checkboxes (Legendary, Sub-legendary, Restricted, Mythical, Paradox, Ultra Beast; checked = included), and the four form toggles (Megas, Regional forms, Gender forms, Other forms).
  4. **Result**: a live count ("312 Pokémon match") that updates as controls change, and a preview table (display name, form, types, six stats, total, tags) paged at 100 rows with the same table-or-cards rule as the pool table.
  5. **Price by stat total**: a toggle plus the 20-row bands table (points, minimum total), with "Reset bands".
  6. **Apply to pool**: replaces the pool with the result priced by bands (or at `DEFAULT_POINTS` when pricing is manual); when the pool is not empty a `Dialog` confirms ("Replace pool"), with a second choice "Add missing only" that keeps existing rows and prices and appends the rest. After applying, the existing table is the place for manual tweaks. **Rebuild from rules** on a loaded format that carries `rules` re-applies them, confirming first ("Rebuild from rules?").
  7. **Keep the prices you edited?**: when a price was edited by hand on a bands-priced pool, Save and Export first ask "Keep manual prices" (the format is saved with `pricing.mode = "manual"`, so a rebuild adds every Pokémon at `DEFAULT_POINTS`) or "Keep the bands" (the bands are saved; the edited prices stay in this pool and a rebuild prices by the bands again). The answer is remembered until the pool changes again.
  - The card's controls are `Field`-labelled, the count is a `role="status"` region, and the whole card collapses on mobile behind a "Build from rules" / "Hide rules" disclosure so a coach who only wants to add one Pokémon is not scrolled past it. The bands table's points cell is a `<td>` (the a11y review test requires every builder `<th>` to be `scope="col"`).
- **Format library**: rows that carry `rules` show a small line under the name ("Champions · Regulation Set M-C · max total 600"), from `describeRules`.
- **Add by name** keeps working and now resolves against the dataset first (any display name or slug), then the existing PokéAPI fallback.
- **Existing formats**: loading one without `rules` shows the rule card in its default state with "This format was built by hand"; saving keeps it without `rules` unless the user applies rules.
- Sprites for form rows come from the dataset's `sprite_url`; the `PokemonSprite` component gets the URL from the dex map as before.

### 13.9 Migration and release order

1. Apply `20260916120000_pool_builder.sql` in the SQL editor (after the hardening and playoffs files; it ends with `select * from public._migration_report();` like them).
2. Run `npm run seed:pokemon` with the service-role key in `.env.scripts` (the file every script reads, section 10 step 3; the key stays out of `.env.local`): 1,237 upserts in the 2026-09-16 build, then it deletes rows that left the file and prints the counts.
3. Deploy the client. Until step 2 runs, the builder shows an empty-state ("The Pokémon dataset has not been loaded yet") and the rest of the app keeps using `pokemon_dex`; the previous client keeps working after step 1 because the file adds no function and changes no policy on the other tables.
4. To refresh data later: `npm run data:pokemon` (`node scripts/build-pokemon-data.mjs`, add `-- --refresh-serebii` to re-fetch the Champions regulation pages), review the diff of `data/pokemon/*.json` and `report.json`, commit, run the seed again.
